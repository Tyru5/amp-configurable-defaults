The extension.
Inside the Windows app.

The native Windows Amp app can load this unpacked Chrome extension through its Edge WebView2 runtime. No patched executable, running injection helper, or remote-debugging port is needed. This is an independent workaround, not an official Amp install path.

Tested with Windows Amp 0.456.19239.0, x64, Edge WebView2 157.0.4341.42, and extension source 1.4.2. Sidebar placement and settings were verified. Full native-app feature coverage and other versions remain untested.

How this setup works.

This experimental setup uses a Windows WebView2 registry policy to load the unpacked extension. It is not an official Amp install path.

The registry mechanism is documented by Microsoft. The enabling switch is internal and may stop working after an Amp or WebView2 update. This does not grant an Amp account, bypass sign-in, or make the extension work on other server URLs.

Reference: Microsoft's WebView2 environment and registry reference.

Set it up in Windows.

Only load source you trust. The extension runs in your signed-in Amp session. These commands change a persistent, per-user registry policy for Amp.exe only, not every WebView2 app. Do not use a wildcard policy or disable browser security protections.

  1. Download source to a permanent folder.

    Download and extract the source ZIP, or use a clone of the repository. This is the unreleased 1.4.2 source, not the store's 1.4.1 package. Find the folder directly containing manifest.json. You do not need to install it in Chrome first.

    The example below uses C:\Tools\amp-configurable-defaults-main. Change that path to your extracted folder. Keep it in place. Loading a Windows-accessible WSL UNC path was also verified, but loading while WSL is stopped was not. A Windows folder avoids that dependency.

  2. Finish active work and fully quit Amp.

    Close the app before changing its launch configuration. Opening another window can reuse the existing process and its old flags. If it remains running, confirm Amp.exe has exited in Task Manager before relaunching. Do not force-close an active session.

  3. Set the app-specific WebView2 arguments.

    Open Windows PowerShell as your usual Windows account. Administrator access was required on the tested machine; if access is denied, use Run as administrator for that same account. On a managed machine, ask your administrator instead of overriding policy.

    Edit $extension, then run this block. It checks for the manifest and refuses to replace an existing Amp.exe value. If one exists, preserve its exact value and have its owner review how to combine the arguments before proceeding. 

    $extension = 'C:\Tools\amp-configurable-defaults-main'
$key = 'HKCU:\Software\Policies\Microsoft\Edge\WebView2\AdditionalBrowserArguments'

if (-not (Test-Path -LiteralPath (Join-Path $extension 'manifest.json'))) {
  throw 'Extension manifest not found. Correct $extension first.'
} elseif ($null -ne (Get-ItemProperty -LiteralPath $key -Name 'Amp.exe' -ErrorAction SilentlyContinue)) {
  throw 'Amp.exe arguments already exist. Preserve and review them first.'
} else {
  if (-not (Test-Path -LiteralPath $key)) {
    New-Item -Path $key -Force -ErrorAction Stop | Out-Null
  }
  $arguments = '--embedded-browser-webview-enable-extension --load-extension="' + $extension + '"'
  New-ItemProperty -LiteralPath $key -Name 'Amp.exe' -PropertyType String -Value $arguments -ErrorAction Stop | Out-Null
  Get-ItemProperty -LiteralPath $key -Name 'Amp.exe'
}

    This creates a REG_SZ value named Amp.exe. The two switches must appear together. No debug port or --disable-features flag is needed.

  4. Launch Amp normally.

    Open Amp from the Start menu and sign in if needed. With default settings and a window at least 768px wide, navigation moves right. Open the gear in Amp's sidebar header to change settings. There is no Chrome toolbar inside the app.

Check it loaded. Know the limits.

Open the sidebar gear and toggle Indent child threads or sidebar placement. The prior native-app test verified the right sidebar, settings panel, immediate setting changes, Escape and outside-click dismissal, storage, and service-worker messaging. It did not certify every feature. In particular, split-pane framing and all composer and reading-panel behaviors still need native-app testing.

  • If nothing appears, check the folder and manifest path, both flags, desktop window width, and that Amp fully restarted. Higher-priority machine policy or environment overrides can take precedence over this per-user value.
  • Settings belong to the app's WebView2 profile, not your Chrome profile. Moving the source folder can change the extension ID and start fresh settings. Neither profile syncs these preferences.
  • The app loads the files currently at the configured path. Updating a clone also changes what it loads. Fully restart Amp after updating source; the native app has no Chrome extensions Reload button.
  • Do not open a remote-debugging port for this setup. A local debugger could control your signed-in session. The final verified configuration had no debugging port open.
  • Split panes use a scoped framing and Content Security Policy exception. Read the security disclosure before using them, even where the extension loads successfully.

Undo the Windows setup.

Fully quit Amp, remove only the value created above, then relaunch. This leaves unrelated WebView2 policies intact. It stops loading the extension; it does not delete the source folder or saved extension data. 

$key = 'HKCU:\Software\Policies\Microsoft\Edge\WebView2\AdditionalBrowserArguments'
Remove-ItemProperty -LiteralPath $key -Name 'Amp.exe' -ErrorAction Stop

If you combined these switches with a pre-existing value, restore that original value instead of deleting it. Do not delete the entire WebView2 policy key. Use the same account and elevation as setup.

Why this does not enable the Mac app.

This method depends on Microsoft's Windows WebView2 runtime and a Windows registry policy. Neither is a cross-platform Amp extension setting. Copying these flags into a Mac launch command is not an established install method.

Testing covered the Windows app only. We have no verified native Mac setup, not evidence that every possible Mac approach is impossible. On macOS, use the extension in desktop Chrome or a Chrome-installed PWA.
